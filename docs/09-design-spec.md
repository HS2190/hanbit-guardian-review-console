## 0. 적용 스킬과 서열

**적용**: `split-layout-technical`(주축, 구조) + `make-interfaces-feel-better`(디테일 3항목만). 토큰 골격은 `figma-variables-tokens-generator`의 3-tier(Primitives → Semantic → Component) 명명을 따르고, `impeccable`은 §9 자체 QA에만 쓴다. **서열: PRD §12 의미 제약 5 > NFR-04/05 > 주축 스킬 구조 규칙 > 보조 스킬 폴리시 > 스킬 장식 항목(삭제).**

스킬 문법을 무드가 아니라 **구조에 대응**시킨 표. 각 행이 "왜 이 스킬인가"의 근거다.

## 1. 의미 제약용 색·형태 체계 (PRD §12 — 스킬이 비워 둔 것, 신설)

원칙: **의미는 형태·접두 라벨·위치가 먼저 나르고, 색은 그 뒤를 따른다**(NFR-04). 색상 계열은 4개뿐이고 각 계열의 뜻을 화면 전체에서 하나로 고정한다.

| 색 계열 | 고정된 뜻 | 쓰이는 곳 | 쓰지 않는 곳 |
|---|---|---|---|
| `ink`(회색 척도) | 사실·중립·잠김·차단(구조적 상태) | 본문, 처리 축 기본, 지급 "완료" 바, BlockCard 좌측 바, 비가역 버튼 | — |
| `accent`(파랑 1색) | 활성·포커스·정보·"발행 대상 변경값"·"확정" | 버튼 primary, 포커스 링, InfoBanner, DiffTable 변경 열, 지급 "지급 확정" 바, 처리 "심사 중" | 판정 결과(유효/반려)에는 금지 |
| `hold`(앰버) | **진행 전에 당신의 주의가 필요함** — 대기·기한·오적용 주의·재심 | 처리 축 대기 4값, DeadlineBadge, PolicyDiffMarker warn, RereviewBanner, 지급 "확정 대기"·"조정 중" | 에러에는 금지(에러는 red) |
| `valid`(초록) | 결과 축 "유효·최초" **하나만** | StatusBadge result=valid_first | 지급 완료·성공 토스트에 금지(초록=유효라는 1:1 대응을 지킴) |
| `reject`(빨강) | 결과 축 "반려" · 시스템 에러 · danger 버튼 | StatusBadge result=rejected, ErrorBanner/InlineError, Button danger-irreversible | **유효·0원·해당 없음(한도 소진)·중복·범위 외·증빙 불충분에 금지**(PRD 제약 2·FR-17) |
| `slate`(청회) | 결과 축 "유효 아님이지만 반려도 아님" — 중복·범위 외·증빙 불충분 | StatusBadge result=duplicate/out_of_scope/insufficient | 그 외 금지 |

### 1.1 제약 ② — 3축 배지 3계열 (형태 × 접두 × 색)

세 축을 **형태**로 먼저 가른다. 색이 겹쳐도(예: 처리 "심사 중"과 지급 "지급 확정"이 둘 다 accent) 형태와 접두 라벨이 축을 말한다.

| 축 | 형태 | 접두 라벨(고정, 색 외 단서) | 값별 색 | 왜 이 형태인가 |
|---|---|---|---|---|
| 처리 `processing` | **outline pill**(radius full, 1px stroke, 투명 fill) | `처리` | 접수 ink-500 stroke·text / 심사 중 accent / 보완 대기·선행 판정 대기·재심 대상·재심 중 hold(+ 앞에 6px 점) / 심사 완료 ink-900 stroke + "✓" 글리프 | "어디에 있나"는 경로 위의 위치 → 가볍고 열린 형태 |
| 결과 `result` | **filled tint rect**(radius 4, fill 있음, stroke 없음) | `결과` | — ink-500 on grey-100 / 유효·최초 green-700 on green-050 / 중복·범위 외·증빙 불충분 slate-700 on slate-100 / 반려 red-800 on red-050 | "판정"은 찍힌 도장 → 면이 있는 닫힌 형태 |
| 지급 `payout` | **left-bar rect**(radius 0, 좌측 3px 바 + 투명 fill, 값은 mono) | `지급` | 미정 bar grey-200 text ink-500 / 확정 대기(범위) bar hold text ink-900 / 지급 확정 N bar accent text ink-900 / 완료 N bar ink-900 text ink-900 / 조정 중 bar hold / 해당 없음(사유) bar grey-200 text ink-500 — **사유 괄호 병기 필수** | "돈"은 장부의 줄 → 통장 행처럼 좌측 바 + 등폭 숫자 |

"유효·0원"(002-F)의 헤더: `[결과 유효·최초]`(초록 면) + `[지급 해당 없음(한도 소진)]`(회색 바) — 초록이 남아 있고 빨강이 없으므로 반려로 읽히지 않는다(확정). 큐 #1107 행은 `[결과 중복(#1103)]`(slate 면) + `[지급 해당 없음(중복)]`(회색 바).

### 1.2 제약 ④ — 차단 카드 vs 에러 vs 정보 배너

| | BlockCard(차단) | ErrorBanner / InlineError(에러) | InfoBanner(정보, T37) |
|---|---|---|---|
| 뜻 | 규칙상 지금 확정할 수 없음 — 이유 + 다음 행동 | 시스템이 실패함 — 재시도 | 되긴 되는데 알아 둘 것 |
| 면 | `surface/sunken`(#EDEFF2) + 1px `line/strong` + **좌측 3px ink-900 바** | `red-050` + 1px red-700 + 아이콘 alert | `accent-050` + 좌측 3px accent 바(테두리 없음) |
| 제목 | "확정 차단 — 사유: 금액" (ink-900 600) | "저장하지 못했습니다" (red-800 600) | 제목 없음, 본문 1줄 |
| 위치 | 판정 패널의 **확정 버튼 자리**(대체) | 발생 지점 인라인 / 상단 배너 | 헤더 아래 1줄, 본문 폭 |
| 행동 | secondary 「선행 건 #1042 열기」 | 「재시도」 | ghost 「#1042 열기」 |
| 판정 컨트롤 | 확정 없음(카드가 대체) | 그대로(입력 보존) | **그대로** |

세 가지가 서로 다른 색 계열(ink / red / accent)이면서 형태(바+테두리 / 테두리+아이콘 / 바만)도 다르다. 이유 없는 비활성 버튼은 어디에도 없다 — 비활성이 필요한 두 곳(POL-C 「다음」, 집계 중 발행 버튼)은 **사유 텍스트가 옆에 붙는 것이 사양**이다.

### 1.3 제약 ⑤ — 가역 vs 비가역

| | 가역(착수·보완 요청·판정 저장·별건·초안) | 비가역(확정·발행·재심 확정·반려) |
|---|---|---|
| 버튼 | `primary`(accent fill) / `secondary` | `irreversible`(ink-900 fill, 좌측 lock 글리프, 라벨에 금액·"— 되돌릴 수 없음" 접미) · 반려만 `danger-irreversible`(red-700 fill) |
| 다이얼로그 | 헤더 흰색, 제목 ink-900, Enter로 확인 가능 | 헤더 상단 4px ink-900 띠 + 우상단 outline 태그 `비가역`(전부 한글이라 `sans/label-12` — §2.3 규칙), 본문 첫 줄에 결과 문장(최종액·잠금·안내 발송), **초기 포커스 = 취소**, Enter 단독 실행 금지(확인 버튼은 클릭 또는 Tab 이동 후 Space/Enter) |
| 완료 피드백 | 정적 전환 | 정적 전환 + 토스트 1회 |
