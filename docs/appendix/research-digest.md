## 3. 규칙 검증 — 반례 손계산 4건 (가상 사례, 결정 아님)

공통 설정: 이벤트 E, 결함 기준액 30,000원, 개인 한도 단위 = 고객×이벤트(버전 바뀌어도 누적 유지), 중복·무효는 한도 미소비. "접수순"은 과제 정본 선택, "확정순"은 과제 정본의 버린 대안 3.

| # | 사례 | 접수순 배정 결과 | 확정순 배정 결과 | 검증 포인트 |
|---|---|---|---|---|
| R1 | **한도 하향 후 접수 건이 기존 누적보다 낮은 한도를 가짐.** 고객 K: 제보 A 09:00 접수(v1, 한도 50,000) → v2 발행(한도 20,000) → 제보 B 10:00 접수(v2). **전제**: A·B는 서로 다른 결함의 최초 유효 제보, K의 기존 누적액 0. 둘 다 미확정 | A 30,000 (v1 잔여 50,000) → B: v2 한도 20,000 − 누적 30,000 = **0원**(음수는 0으로 절삭, 환수 없음). 합 30,000 | 담당자가 A→B: 30,000 / 0. **B→A**: B 20,000(v2 잔여 20,000) → A 30,000(v1 잔여 50,000−20,000). 합 **50,000**. 처리 순서에 따라 합계 30,000 또는 50,000 | 접수순은 고객에게 *항상 더 주는* 방식이 아니다(여기선 덜 주거나 같다 — 확정순 A→B는 접수순과 동일). 얻는 것은 담당자 순서가 결과·총액을 바꾸지 않는 것. **PM 확인 필요**: "잔여 음수 → 0 절삭"을 규칙으로 명시할지 |
| R2 | **중복 선행 대기 검증 — 다른 고객의 앞선 제보가 보완 대기였다가 무효.** 고객 P 제보 A 09:00(증빙 불충분 → 보완 대기). 고객 Q 제보 B 09:30, 같은 결함 후보 | A 판정 전 B의 최초 지위 확정 불가 — 배정 방식 무관. B "선행 판정 대기". A 보완 만료·무효 → B 자동 재검토(자동 승인 아님) → 독립 유효성 통과 시 B 최초 유효 30,000, A 한도 미소비. A 보완 완료·유효 → A 최초 유효, B 중복 | 동일. A 판정 전 B의 최초 지위 확정 불가 — 배정 방식 무관. 대기는 "최초 유효자" 조건(더 이른 후보의 유효성이 먼저 정해져야 함)에서 오므로 한도 배정 순서와 관계없음 | 이 대기는 접수순의 대가가 아니라 **최초 유효자 규칙의 대가**. B의 대기 기간 = A의 보완 만료 기간(HackerOne 30일은 참고치) → §4 위험 2. 접수순의 진짜 대가는 R2′ |
| R2′ | **같은 고객의 선행 건 미판정 + 후속 건 유효.** 고객 K(한도 50,000, 누적 0): 제보 A 09:00 접수(결함 X, 증빙 불충분 → 보완 대기) → 제보 B 09:30 접수(결함 Y, 유효·최초). 서로 다른 결함 | 접수순이므로 A가 한도를 먼저 소비할 수 있음(A 유효 시 30,000). 따라서 A 판정 전에는 B의 금액을 잠글 수 없음 → B "선행 판정 대기"(유효성은 정해졌으나 금액 미확정). A 유효 → A 30,000·B 20,000. A 무효 → B 30,000 | B를 지금 확정·잠금 30,000. A는 나중에 유효해도 잔여 20,000 | **접수순의 진짜 대가**: 같은 고객의 선행 건이 미판정이면 후속 건 확정이 지연된다. 총액은 양쪽 같음(A 유효 시 50,000, 무효 시 30,000), 달라지는 것은 배분과 확정 시점 |
| R3 | **잔여 한도 0원인 최초 유효자 + 차순위 존재.** 고객 K(누적 50,000/50,000) 제보 A 10:00. 고객 M 제보 B 10:20, 같은 결함 | A 유효·최초, 한도 잔여 0 → **유효·0원**(반려 아님, 한도 미소비). B 중복(원본 A) → 0원 | 동일(A 0원, B 중복). 최초 유효자 판정은 배정 순서와 무관 | 결함은 A 덕에 고쳐졌으나 아무도 못 받는 결과. 과제 정본은 "지위 불이전"을 선택했으므로 이는 규칙의 의도된 결과 — 고객 K·M 각각에 대한 안내 문구가 필요. 지위 이전(B 30,000)은 버린 선택지로 대안 비교에 쓸 수 있음 |
| R4 | **앞선 판정이 재심에서 뒤집혔는데 후속 금액이 이미 잠김.** 고객 K: 제보 A 확정·지급 30,000(v1 한도 50,000) → 제보 C 확정 20,000(잔여) → A 재심에서 무효(증빙 조작). **전제**: C도 한도 50,000원 정책의 별도 최초 유효 제보(A와 다른 결함) | C는 잠금 유지 20,000. A 무효 → 한도 미소비로 재계산하면 A 제외 시 잔여 50,000 → C 후보액 30,000 → 기존 확정 20,000 대비 +10,000이지만 잠금이라 자동 재계산 없음. A 30,000 환수·C 10,000 추가는 **본사 조정** 대상 | 동일(잠금 규칙은 양쪽 공통) | 잠금은 결정이 흔들리지 않게 하는 대신 사후 정정 경로(조정)를 요구. 변형: A 최초 유효 → 타 고객 B 중복 확정 → A 재심 무효 시 B는 "중복" 잠금 상태 — **재심으로 관계가 바뀌면 하류 건도 재심 대상**(자동 승인 아님)이 규칙에 필요 |

요약: 접수순은 고객에게 항상 더 주는 방식이 아니라 **처리 순서가 결과를 바꾸지 않게 하는 방식**이며, 대가는 같은 고객의 선행 건이 미판정일 때 후속 건 확정 지연(R2′)이다. R2의 중복 선행 대기는 배정 방식과 무관한 최초 유효자 규칙의 대가다.

**기획자/PM 확정 필요**(리서치는 결정하지 않는다 — 질문만):
- R1 잔여 음수 → 0 절삭을 규칙으로 명시할지(환수 없음).
- R3 지위 불이전 결과에 대한 고객 K·M 각각의 안내 문구.
- R4 재심으로 관계가 바뀌면 하류 건도 재심 대상(자동 승인 아님)으로 둘지 — 과제 정본에 아직 없는 규칙.
- 보완과 우선순위의 경계: 정상 접수로 순위를 갖는 최소 증빙은 무엇인가 / 보완 중 기존 접수 순위를 어디까지 유지하는가 / 보완 기한과 만료 시 결과는 무엇인가(기간 수치는 PM 결정).
- 재심 무효 시 한도 복원 시점: 판정 무효화·한도 복원·현금 환수는 서로 다른 사건이다 — 무효 즉시 복원인가, 본사 조정 확정·환수까지 대기인가, 조정 중 접수되는 후속 제보는 어느 한도로 산정하는가.
- 재심(이의 제기) 요청 가능 기간·횟수.

## 4. 미검증 위험 3개 (실사용자 검증 없음)

1. **사건 구분의 증빙 실현 가능성** — "같은 원인·같은 시정 대상인가"를 사진·시각·위치만으로 판별할 수 있는지 확인된 바 없다. 같은 SKU 파손품 2개를 서로 다른 개체로 증명하려면 개체 식별(위치·사진 각도·시각차)이 필요한데, 고객이 그런 증빙을 낼지, 심사자가 그것으로 구분할 수 있을지 미검증. 로트 단위 불량은 이 질문으로 안 갈린다.
2. **선행 대기의 운영 비용** — R2′처럼 같은 고객의 후속 건이 선행 건의 보완 만료까지 대기하면 큐 체류가 길어진다(R2의 중복 선행 대기는 배정 방식과 무관하지만 같은 체류 비용을 낸다). 대기 건 비율·평균 대기일·만료 기간 적정치는 데이터가 없다(HackerOne 30일은 다른 도메인의 참고치). 대기 이유를 UI에 노출한다는 계획은 있으나 그것이 체류 자체를 줄이진 않는다.
3. **핵심 화면 이해 가능성** — 심사 상세·정책 발행 화면이 아래 3질문에 사용자가 답할 수 있게 만드는지는 로파이에서 확인해야 한다(현재 0명 검증): ① 왜 현재 정책이 아닌 접수 당시 정책인가 ② 정책을 낮추면 기존 부담도 주는가 ③ 지금 확정 못 하는 이유와 다음 행동은 무엇인가.

## 5. 범위 밖 (한 줄씩)

- 다수 제보자 기여도 배분(권익위 §80) — 과제의 "최초 유효자 1명 지급" 조건과 다른 모델.
- 정책 버전 아카이브·타임라인 탐색 패턴 — 상세의 근거 패널로 축약, 별도 리서치 없음.
- 큐 처리량·대기 건 예측 — 데이터 없음, 기획 단계에서 한 줄 리스크로.
- 상향 직전 제보 투척 등 어뷰저 — 리서치 대상 아님.
- 심사관 다수 간 일관성 — 리서치 대상 아님(디자이너 단계 diff view 레퍼런스는 별도).
