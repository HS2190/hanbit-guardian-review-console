# 부록 · 무엇을 확인하면 되는가

읽는 문서의 주장이 검증 가능한 형태로 쓰였다는 것을 보이는 문서입니다. 요구사항 스물다섯 개를 나열하는 대신, **무엇을 해보면 무엇이 나와야 하는가**로 옮겼습니다. 프로토타입에서 그대로 눌러 볼 수 있는 항목에는 표시를 해 두었습니다.

## 단일 원칙이 지켜지는가

| 확인 행동 | 나와야 하는 결과 | |
|---|---|---|
| v2 발효 이후에 v1 시점 접수 건을 연다 | 적용 정책이 v1로 표시되고 잠금 표시가 붙는다. 현재 정책은 캡션 한 줄로만 보인다 | 프로토타입 |
| 심사 화면에서 적용 정책을 바꿀 방법을 찾는다 | 어떤 컨트롤도 없다. 바꿀 수 있는 것은 결함 유형 · 중복 관계 · 유효성뿐이다 | 프로토타입 |
| 발효 시각 전후로 접수된 두 건을 비교한다 | 같은 결함 유형인데 기준액이 다르다 | 프로토타입 |
| 정책을 발행한 뒤 기존 건을 다시 연다 | 적용 정책과 금액이 그대로다 | 프로토타입 |

## 판정 순서가 고정돼 있는가

| 확인 행동 | 나와야 하는 결과 | |
|---|---|---|
| 접수 당시 범위 밖인 건을 판정한다 | 증빙을 보지 않고 범위 외로 종결된다 | 프로토타입 |
| 증빙이 불충분한 건을 판정한다 | 중복을 보지 않고 보완 단계로 간다 | 프로토타입 |
| 같은 상품·같은 결함의 더 이른 유효 건이 있는 건을 판정한다 | 중복으로 판정되고 원본 번호가 함께 남는다 | 프로토타입 |
| 같은 상품이지만 조치 완료 이후에 재발한 건을 판정한다 | 중복이 아니라 별건으로 처리된다 | 프로토타입 |
| 한도를 이미 쓴 고객의 새 건을 판정한다 | 결과는 유효로 남고 지급만 해당 없음이 되며 사유가 한도 소진으로 적힌다 | 프로토타입 |

## 접수순 배정의 대가가 화면에 드러나는가

| 확인 행동 | 나와야 하는 결과 | |
|---|---|---|
| 같은 고객의 선행 건이 미판정인 건을 연다 | 확정 버튼 자리에 차단 카드가 서고, 막힌 이유와 대상 건으로 가는 버튼이 함께 있다 | 프로토타입 |
| 그 선행 건을 확정한다 | 뒤 건이 잔여 한도로 열린다 | 프로토타입 |
| 선행 건을 무효로 만든다 | 뒤 건이 전액으로 열린다 | 프로토타입 |

## 바꾸기 전에 영향을 보는가

| 확인 행동 | 나와야 하는 결과 | |
|---|---|---|
| 정책 금액을 바꾸고 발행을 시도한다 | 발행 전에 영향 확인 단계를 지나야 한다 | 프로토타입 |
| 영향 확인 화면을 읽는다 | 지급 완료 · 확정 미송금 · 미확정 기준액이 분리돼 있고, 미확정 합계에는 조건이 함께 적혀 있다 | 프로토타입 |
| 아무것도 바꾸지 않고 발행을 시도한다 | 버튼이 막히고 그 이유가 적혀 있다 | 프로토타입 |

## 기록이 남는가

- 모든 판정과 수정과 발행에 행위자와 시각과 이전 값과 이후 값과 사유가 남습니다.
- 결함 유형을 바꾸려면 사유가 필요합니다.
- 중복으로 판정하려면 원본 지정이 필요합니다.
- 확정과 발행은 되돌릴 수 없고, 확인 창에서 그 사실을 문장으로 말합니다.

## 아직 확인하지 못한 것

- 심사자가 이 흐름을 실제로 어떻게 느끼는지는 검증하지 못했습니다. 다섯 명에게 과업을 주고 막히는 지점을 보는 것이 첫 순서입니다.
- 보완 1회와 기한 7일, 이의 제기 14일은 가설입니다. 운영 데이터로 정할 값입니다.
- 동시 편집 시 누가 보고 있는지 표시하는 장치는 만들지 않았습니다.
