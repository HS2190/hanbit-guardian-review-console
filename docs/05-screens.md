# 05 · 화면 결정

화면 서른아홉 장의 목록이 아니라, 배치를 가른 판단만 적습니다. 전체 화면은 Figma에, 레드라인과 컴포넌트 규칙은 부록에 있습니다.

## 의미 제약 다섯을 화면으로 옮기기

요구사항 문서에 "이걸 어기면 요구사항 실패"로 못 박은 다섯 가지가 있습니다. 화면 설계는 이 다섯의 번역입니다.

| 제약 | 화면에서의 번역 |
|---|---|
| 적용 정책과 현재 정책을 색으로 승격하지 말 것 | 적용은 큰 제목과 자물쇠로, 현재는 아래 한 줄 캡션으로. 화살표는 정책 비교 표에서만 쓴다 |
| 세 축이 서로 다른 축으로 읽힐 것 | 열을 분리하고 배지에 처리 · 결과 · 지급 접두어를 붙인다. 색 외의 단서를 병기한다 |
| 금액은 계산 순서대로 읽힐 것 | 기준액 → 한도 조정 → 최종을 세로 세 줄로. 절삭은 계산식이 보이게 |
| 차단과 에러와 정보를 구분할 것 | 차단은 판정 패널 안 카드, 에러는 상단 배너, 정보는 중립 배너. 이유 없는 비활성은 두지 않는다 |
| 유효 0원은 반려가 아닐 것 | 결과 배지는 유효로, 지급 배지는 해당 없음에 사유 괄호로. 두 행을 합치지 않는다 |

## 큐 — 훑는 화면

열세 행에 열두 열입니다. 훑으면서 무엇을 먼저 열지 정하는 자리라 정보를 줄이지 않고 정렬을 고정했습니다.

- **세 축을 각각 열로.** 한 행에서 처리와 결과와 지급이 나란히 보입니다.
- **보류 사유를 따로 열에.** 왜 멈춰 있는지가 배지 안에 숨지 않게 했습니다.
- **정책 차이는 사실만.** 적용과 현재가 다르면 "적용 ≠ 현재"만 띄웁니다. 처음에는 현재 금액을 배지에 넣었는데, 그것이 현재 정책을 승격시켜 심사자가 그 값으로 판단할 위험을 만든다는 지적을 받고 금액을 뺐습니다.
- **상태 카운터를 필터로.** 여덟 개 칩이 곧 필터입니다. 사유 합계가 건수와 다를 수 있다는 단서를 칩 아래 상시 노출합니다.

## 목록과 상세를 어떻게 둘 것인가

큐에서 건을 고른 다음 무엇을 보여줄지를 세 가지로 그려 놓고 실제로 재 봤습니다.

| | 1안 · 별도 상세 화면 | 2안 · 목록 옆 미리보기 | 3안 · 접히는 레일 |
|---|---|---|---|
| 큐에 보이는 열 | 12 | 5 | 12 (선택 전) |
| 상세 세로 길이 | 1,839px | 2,608px | 1,839px |
| 판정 패널 위치 | 위에서 448px | 위에서 2,318px | 위에서 448px |
| 건 사이 이동 | 화면 전환 | 목록 유지 | 레일 유지 |

2안은 목록이 남는 대신 대가가 컸습니다. 상세 폭이 좁아져 같은 내용이 42퍼센트 길어졌고, 판정 패널이 본문 아래로 밀려 주 버튼에 닿으려면 화면 두 개 반을 내려야 했습니다. 큐도 다섯 열로 줄어 훑으면서 우선순위를 정할 수 없었습니다.

**3안을 골랐습니다.** 선택 전에는 1안처럼 열두 열을 전체 폭으로 펴고, 건을 고르면 목록이 폭 260 레일로 접힙니다. 레일에는 번호와 접수 시각과 처리 배지만 남습니다. 식별과 순서와 왜 멈춰 있는지, 다음 건으로 넘어가는 데 필요한 최소입니다. 상세는 판정 패널 340을 오른쪽 고정 열로 두고 본문이 남는 폭을 씁니다. 근거와 행동이 한 화면에 남습니다. 본문은 1440에서 760, 1366에서 686, 1280에서 600으로 줄고 패널과 레일은 고정입니다 — 세 폭 모두 가로 스크롤 없이 주 행동 버튼까지 들어갑니다.

## 심사 상세 — 판단하는 화면

첫 화면에서 스크롤 없이 세 가지가 보여야 한다고 정했습니다. 접수 근거, 산정 상태, 막혔다면 그 이유입니다.

- **요약 카드 한 장.** 적용 정책과 산정과 다음 행동이 한 줄에 섭니다. 금액보다 "어느 시점 기준인가"가 먼저 읽히도록 적용 정책을 가장 크게 두었습니다.
- **본문은 판단 순서대로.** 접수 근거, 증빙, 중복 후보, 산정 과정, 고객 안내 근거, 활동 이력 순입니다. 판정 순서 다섯 단계와 같은 순서입니다.
- **판정 패널은 오른쪽 고정.** 주 버튼은 언제나 하나이고, 스크롤을 내려도 따라옵니다. 조건이 갖춰지지 않으면 버튼 대신 차단 카드가 서고 막힌 이유와 갈 곳을 함께 줍니다.
- **되돌릴 수 없는 행동은 라벨에 값을 넣습니다.** "지급 확정 30,000원"처럼 결정값을 적고, 확인 버튼에는 되돌릴 수 없다는 말을 붙입니다.

## 정책 — 바꾸는 화면

현황, 편집, 영향 확인, 완료의 네 단계입니다. 세 번째 단계가 이 흐름의 이유입니다.

영향 확인은 세 숫자를 분리해서 보여줍니다. 지급 완료, 지급 확정이지만 미송금, 미확정 기준액 합계입니다. 마지막 것을 "예상 지급액"이라 부르지 않습니다. 재분류가 일어나면 합계가 바뀌고 중복과 한도도 반영되지 않은 값이라, 예상이라고 부르면 가짜 정밀도가 됩니다. 대신 조건을 그대로 적습니다.

그리고 방향을 한 문장으로 고정했습니다. 이미 접수된 건의 적용 조건은 바뀌지 않고, 새 값은 발효 이후 접수분부터라는 문장입니다.

## 의도적으로 하지 않은 것

- **정책 선택 UI를 두지 않았습니다.** 적용 정책을 고르는 드롭다운 하나면 이 설계가 무너집니다.
- **중복을 자동 확정하지 않습니다.** 후보만 제시하고 판정은 사람이 합니다. 상품 코드가 같다고 같은 사건은 아니기 때문입니다.
- **1280 미만은 지원하지 않습니다.** 열두 열짜리 표를 좁은 화면에 넣으면 정렬이 무너집니다. 미지원이라고 화면에서 밝힙니다.
- **재심 전용 화면을 따로 만들지 않았습니다.** 닷새 안에서 우선순위를 낮추고 상세 화면의 변형으로 처리했습니다.
