# 06 · 검수 기록

각 단계 산출물은 다음 단계로 넘어가기 전에 검수를 거쳤습니다. 검수는 결함을 찾는 용도였고, 지적을 받아들일지와 어떻게 고칠지는 제가 정했습니다. 아래는 실제로 설계를 바꾼 지적만 추렸습니다.

## 하이파이 1차 → 디자인 시스템 적용 재제작

1차 하이파이는 이 과제 전용 토큰과 컴포넌트를 새로 만들었습니다. 결과가 정돈되지 않았습니다. 사이드바와 상단바와 브레드크럼이 세 겹이었고, 같은 무게의 박스가 셋 나란히 섰고, 배지 크기가 제각각이었습니다.

시스템이 없어서가 아니라 위계가 없어서였습니다. 개인 디자인 시스템을 연결해 서른세 장을 다시 그리면서 셸을 두 줄로, 요약 카드를 한 장으로, 글자 단계를 다섯으로 줄였습니다.

## 검수가 잡은 결함 네 가지

- **위계 역전.** 영향 확인 화면에서 발행 버튼이 근거보다 먼저 보였습니다. 근거 카드를 차이 표 위로 올리고, 변경된 항목만 펼쳐 두었습니다.
- **모순된 상태.** 연결이 끊긴 에러 화면에서 확정 버튼이 활성이었습니다. 버튼을 차단 카드로 바꾸고 이유와 다음 행동을 함께 적었습니다.
- **문구 이탈.** 화면 문구가 확정된 문구 시트를 쉰두 곳에서 벗어났습니다. 시트를 정본으로 두고 전부 되돌렸습니다.
- **판단의 선점.** "라벨 판독 불가"처럼 심사자가 내려야 할 판단을 시스템이 먼저 단정한 문구가 있었습니다. "증빙 확인 후 유효성 평가"로 바꿨습니다.

## 외부 교차검증

자기가 만든 것을 자기가 검수하면 자기참조가 됩니다. 다른 관점이 필요한 지점에서만 외부 모델에 화면을 보여 교차검증했습니다.

가장 값있는 지적은 큐의 정책 열에 있던 배지였습니다. 적용 정책과 현재 정책이 다를 때 현재 금액을 배지로 띄우고 있었는데, 이것이 "현재 정책"을 승격시켜 심사자가 그 값으로 판단할 위험을 만든다는 지적이었습니다. 큐에 필요한 의미는 "적용이 최신이 아님"이지 "현재가 얼마"가 아니므로, 금액을 빼고 차이만 표시하도록 고쳤습니다.

## 받아들이지 않은 지적

- **확정 버튼 노출 조건을 체크리스트로 만들라.** 확정 문구와 충돌해 기각했습니다. 조건은 문장 한 줄로 유지했습니다.
- **큐 카운터의 합이 건수와 다르다.** 화면 오류가 아니라 기획이 지정한 대기열 필터의 결과입니다. 주석을 한 줄 더했습니다.
- **사례 수를 낮춰 표현하라.** 근거로 쓴 다섯 건은 공개된 운영 문서와 공지에서 가져온 실제 사례입니다. 표현을 낮추는 대신 출처를 명시했습니다.

## 사용한 도구

검수와 교차검증에는 직접 구축한 멀티에이전트 체계를 사용했습니다. 리서치 근거를 모으고 각 단계 산출물의 결함을 지적하게 하는 용도였습니다. 무엇을 만들지, 지적을 받아들일지, 어떻게 고칠지는 제가 정했습니다.
